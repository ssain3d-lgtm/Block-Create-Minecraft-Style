AI Voxel Architecture Studio — 신규 프로젝트 구축 지시서

최상위 목표

현재 기존 소스코드는 제공되지 않는다.

제공된 에펠탑 프로그램 스크린샷 2장을 시각적 참고 자료로 활용하여 새로운 AI 기반 3D 복셀 건축 스튜디오를 처음부터 구현하라.

목표는 사진 속 화면을 단순 복제하는 것이 아니라, 사진 속 건축 프로그램의 기능을 구현하면서 이를 뛰어넘는 범용 AI 건축 엔진을 만드는 것이다.

기존 소스가 없으므로 기존 코드 분석이나 호환성 유지 작업은 요구하지 않는다.

분석 보고서만 작성하지 말고 실제로 실행 가능한 프로그램을 개발하라.

1. 기술 스택

권장 기술:

- TypeScript
- Three.js
- Vite
- WebGL
- JSON 기반 건축 설계 데이터
- Node.js 기반 CLI 및 도구 API

다른 기술이 유리하다면 그 이유를 설명하고 적용하라.

Windows 환경에서 실행할 수 있어야 하며, 별도 유료 API 없이 기본 건축 기능을 사용 가능해야 한다.

2. 사용자 인터페이스

첨부된 스크린샷을 참고하라.

스크린샷에는 다음 요소가 보인다.

- 밝은 회색 및 흰색 배경
- 짙은 녹색 포인트 컬러
- 좌측 건축 편집 사이드바
- 우측 대형 3D 건축 뷰포트
- 건축물 이름 및 프로젝트 정보
- 전체·정면·측면·상단 카메라 버튼
- 조명 설정
- 블록 추가·삭제·편집
- 큐브·반블록·계단·경사 등의 선택
- 재질 및 색상 팔레트
- 블록 수 및 FPS 표시

위 요소들을 현대적이고 직관적인 UI로 재구성하라.

실제 작동하지 않는 장식용 버튼은 만들지 말 것.

- 3D 좌표 기반 블록 데이터 관리
- 블록 추가, 삭제, 변경

- 청크 기반 데이터 관리

재질은 저장하고 다른 건축 프로젝트에서도 재사용할 수 있도록 한다.

4. AI Native Architecture Engine

이 프로젝트에서 가장 중요한 기능이다.

Qwen, Claude, GPT 등의 LLM이 건축 엔진을 도구로 사용하도록 설계하라.

LLM이 수만 개 블록의 좌표를 직접 작성하지 않아도 되도록 고수준 건축 API를 제공한다.

예시:

createBuilding()
createFoundation()
createWall()
createRoof()
createTower()
createArch()
createTruss()
createCustomBlock()
createMaterial()
placeStructure()
duplicateStructure()
modifyStructure()
inspectStructure()
renderScene()
saveProject()

각 기능은 실제 실행 가능한 구현과 입력 검증을 갖춰야 한다.

JSON 명령과 TypeScript API를 우선 개발하고, 가능하다면 MCP 서버를 추가하라.

Qwen과 OpenCode 같은 로컬 AI 에이전트도 연결할 수 있도록 특정 AI 서비스에 종속되지 않게 만든다.

외부 LLM 연결 없이도 명령을 직접 실행하고 검증할 수 있어야 한다.

5. AI가 스스로 새로운 블록을 만들 수 있게 하라

기존 블록만 선택하는 프로그램이 되어서는 안 된다.

예를 들어 AI가 일본식 기와지붕을 만들고 싶다면:

1. 필요한 형상의 종류를 판단한다.
2. 기존 라이브러리에 적절한 블록이 있는지 검색한다.
3. 없으면 새로운 형상을 파라미터로 생성한다.
4. 재질을 지정한다.
5. 새로운 자산으로 등록한다.
6. 건축에 사용한다.
7. 이후 다른 프로젝트에서도 재사용한다.

이 과정을 지원하는 Asset Factory 및 Asset Registry를 구현하라.

단순한 텍스트 설명이나 샘플 코드가 아니라 실제 3D 형상이 생성되어야 한다.

6. AI 건축 설계 시스템

건축물을 다음 계층으로 관리한다.

- Project: 전체 프로젝트
- Building: 건축물
- Floor/Region: 층과 구역
- Structure: 벽, 지붕, 기둥 등
- Component: 반복 가능한 건축 부품
- Block/Mesh: 실제 렌더링 요소

AI가 건축 계획을 먼저 생성하고, 엔진이 이를 실제 구조물로 변환하는 방식을 구축하라.

건축 명령은 기록하고 재실행할 수 있어야 한다.

특정 구역만 선택하여 다시 시공할 수 있어야 한다.

7. 성능 최적화

참고 사진의 에펠탑에는 10만 개 이상의 블록이 사용되고 있다.

신규 엔진 역시 대규모 건축을 목표로 한다.

다음 기술을 검토하고 적절히 구현하라.

- InstancedMesh
- Chunk Management
- Frustum Culling
- Geometry Batching
- Hidden Face Culling
- Greedy Meshing
- Incremental Updates

10만 블록 규모의 장면에서 로딩·렌더링·편집 성능을 측정하는 벤치마크를 작성하라.

구체적인 FPS는 실제 측정을 통해 보고하고 추정값을 실측값처럼 제시하지 말 것.

8. 예제 건축물

엔진 검증을 위해 다음 예제 프로젝트를 구현하라.

A. 에펠탑

- 철골 트러스
- 반복 구조
- 네 개의 기초 지지대
- 아치
- 전망대
- 상부 타워
- 주변 조경

첨부된 사진을 참고하되 정확히 보이지 않는 부분은 합리적인 구조로 설계한다.

B. 일본 성곽

- 다층 건물
- 일본식 지붕
- 반복 창문
- 석축
- 목재 구조

C. 비대칭 모던하우스

- 돌출 구조물
- 비대칭 배치
- 유리 벽면
- 콘크리트 외벽
- 다양한 지붕 높이

D. AI 전용 테스트

- JSON 명령만으로 집 한 채 제작
- 새로운 경사 블록 생성
- 라이브러리 등록
- 재사용 및 수정
- 저장하고 다시 불러오기

모든 예제를 처음부터 완성할 필요는 없다.

핵심 엔진의 완성도를 우선하고, 최소한 하나의 건축 예제를 실제 작동시켜라.

9. AI 품질 검수

정면·후면·측면·상단 스크린샷을 생성하는 기능을 구현한다.

외부 Vision LLM이 건물 이미지를 검사하고 수정 지시를 전달할 수 있도록 API를 설계한다.

비정상 블록, 누락 구조물, 좌표 오류 등은 가능한 범위에서 프로그램이 직접 검사하도록 한다.

AI가 건물 전체를 재생성하지 않고 선택된 구조물만 수정하도록 지원한다.

10. 개발 우선순위

P0: 반드시 구현

- 실행 가능한 프로젝트

- 기본 복셀 엔진
- 블록 편집
- 저장/불러오기
- JSON 건축 명령 API

- 사용자 정의 블록 생성
- Procedural Structure

- AI 건축 명령 실행
- 건축 테스트 예제

P2: 후속 확장

- MCP 서버
- AI 검사 시스템
- 고급 UI
- 고성능 메시 최적화
- 타임랩스

11. 작업 방식

지금부터 실제 구현을 시작하라.

- 빈 프로젝트라면 필요한 디렉터리와 패키지를 생성한다.
- 적절한 아키텍처를 선택한다.
- 핵심 기능부터 실제 코드로 구현한다.
- 실행 명령과 테스트를 준비한다.
- 오류가 발생하면 수정 후 재검증한다.
- 기능별 완료 여부를 기록한다.
- 시간이 부족할 경우 작동하는 P0/P1 기능을 우선 완성한다.
- 기존 파일이 존재하면 사용자 작업을 임의로 삭제하지 않는다.
- 불필요한 사용자 승인 요청 없이 합리적으로 개발을 진행한다.

프로젝트 루트에 "PROGRESS.md"를 만들고 현재 단계, 완료 기능, 미완료 기능, 실행 방법, 다음 작업을 지속적으로 기록하라.

컨텍스트 압축이나 세션 종료가 발생해도 "PROGRESS.md"를 읽고 개발을 이어갈 수 있도록 한다.

최종적으로는 다음이 가능해야 한다.

사용자가 로컬 LLM에게 '에펠탑을 만들어 줘'라고 요청하면 LLM이 이 엔진의 도구를 호출하여 실제 3D 건축물을 생성할 수 있는 기반을 제공하는 것.

AI와 실제 연결하지 못한 경우라도 건축 도구 API는 독립적으로 동작해야 한다.

문서 작성만으로 작업을 종료하지 마라. 반드시 실행 가능한 코드와 검증 결과를 남겨라.
